Phase 1.2 — Data Cleaning

Pre-Computation Cleaning: Mathematical Integrity

Before any derived metrics could be computed, the dataset was sanitized to prevent critical mathematical failures during downstream statistical modeling.

Denominator Sanitization

All foundational denominator columns were scanned for zero values. Any instance of 0 was replaced with 1 to proactively prevent NaN or Infinity errors from breaking algorithms and dashboard calculations.

Protected columns:

estimated_reach engagements campaign_duration_days 
# data_cleaner.py — Denominator sanitization

# Prevent Division by Zero: replace 0 with 1 in denominator columns
cols_to_protect = ['estimated_reach', 'engagements', 'campaign_duration_days']
for col in cols_to_protect:
    df[col] = df[col].replace(0, 1)

Why this matters: Without this step, computing ratios like engagements / estimated_reach would produce infinite values that silently corrupt regression coefficients, Tableau calculations, and any downstream aggregation.

Transitioning from raw vanity metrics to normalized performance rates. Two engagement-focused KPIs were engineered:

daily_engagement_velocity

Phase 1.2 — Advanced Benchmarking

Platform-Wise Normalization & Outlier Flagging

To enable clean cross-sectional analysis, three advanced normalization columns were engineered on top of the 6 core KPIs.

benchmark_index_true_engagement_rate

Compares every campaign against its specific platform's average engagement rate. An index of 1.0 = platform average. Index 2.5 = outperformed by 150%.

benchmark_index_reach_to_sales_conversion_rate

Same benchmarking logic applied to the growth conversion rate, evaluated strictly against platform-specific averages.

is_viral_outlier Boolean

IQR-based statistical flag. Campaigns with true_engagement_rate > Q3 + 1.5 * IQR are flagged as viral outliers. Crucial for running clean regression baselines without extreme skew.

# Advanced Benchmarking: Platform-wise normalization

    platform_avg = df.groupby('platform')[metric].transform('mean')
    df[f'benchmark_index_{metric}'] = (df[metric] / platform_avg).round(3)

# Outlier Flagging via IQR method
Q1 = df['true_engagement_rate'].quantile(0.25)
Q3 = df['true_engagement_rate'].quantile(0.75)
IQR = Q3 - Q1
upper_bound = Q3 + 1.5 * IQR

df['is_viral_outlier'] = np.where(df['true_engagement_rate'] > upper_bound, True, False)

Phase 1.3 — Data Augmentation

Scaling Architecture: 150K → 1,000,000 Rows

Scaling tabular data for regression requires strict adherence to the original statistical distribution. Generating purely random data would destroy the linear correlations and predictive power. The pipeline uses a hybrid approach.

Step 1: Bootstrapping

Categorical & Structural Baseline

Resampling with Replacement draws 850,000 rows from the clean 150K dataset. Preserves macro-level categorical proportions exactly.

Step 2: Gaussian Noise

Continuous Variable Variance

Injects scaled random noise into numerical columns to break exact duplication while preserving variance, mean, and covariance structure.

Step 3: Merge & Shuffle

Final Assembly

Original 150K + 850K synthetic rows concatenated and randomly shuffled to prevent ordering bias.

Input150,000 rows
Generated850,000 synthetic rows
Output1,000,000 rows
Noise Threshold0.01 (1%)

Phase 1.3 — Bootstrapping

Categorical Preservation via Resampling

For non-continuous variables (platform, influencer_category, campaign_type), altering the data mathematically is impossible. The algorithm uses Resampling with Replacement (Bootstrapping) to create a structural baseline.

The Mechanism

Randomly draws 850,000 rows from the cleaned 150,000-row dataset with replacement. Each sampled row is an exact copy of an original row at this stage.

The Benefit

Guarantees that macro-level categorical proportions — the ratio of YouTube to TikTok campaigns, Fashion to Tech influencers — remain exactly identical to the real-world sample.

Problem: If we only used bootstrapping, the regression model would overfit on exact duplicate numerical values. This is why Gaussian noise injection is applied next.

# Step 1: Bootstrap 850K rows from original
rows_to_generate = target_rows - current_rows

# Sample with replacement
synthetic_base = df.sample(
    n=rows_to_generate,
    replace=True,
    random_state=42
).reset_index(drop=True)

# Separate column types
num_cols = df.select_dtypes(
    include=[np.number]
).columns.tolist()

cat_cols = df.select_dtypes(
    exclude=[np.number]
).columns.tolist()

Phase 1.3 — Gaussian Noise Injection

Vectorized Continuous Variable Variance

For the bootstrapped numerical columns, the algorithm generates a matrix of random noise drawn from a standard normal distribution, scaled proportionately by each column's standard deviation.

New_Value = Original_Value + [N(0, 1) × σcolumn × 0.01]

Where σ is the standard deviation of each specific column, and 0.01 is the strict noise threshold parameter.

1% Variance Threshold

Creates "new" numerical data points that vary only slightly from originals. Breaks exact duplication while strictly preserving the variance, mean, and covariance structure required for accurate OLS regression.

# Vectorized Gaussian Noise Matrix
col_stds = df[num_cols].std().values

noise_matrix = np.random.normal(
    loc=0.0,
    scale=1.0,
    size=(rows_to_generate, len(num_cols))
) * col_stds * noise_std

# Apply noise to numerical columns
synthetic_base[num_cols] = (
    synthetic_base[num_cols] + noise_matrix
)

Phase 1.3 — Architectural Trade-offs

Bypassed Augmentation Techniques

During the design phase, multiple advanced augmentation techniques were evaluated. The following were deliberately bypassed to prioritize computational scalability and data integrity at the 1-million-row scale:

SMOGN — Bypassed

Synthetic Minority Over-Sampling for Regression

While excellent for interpolating skewed target variables, SMOGN relies on K-Nearest Neighbor distance calculations. At a scale of 850,000 generated rows, the algorithmic time complexity O(n²) results in severe memory bottlenecks and potential local hardware crashes. Vectorized noise achieves similar continuous variance at a fraction of the computational cost.

Categorical Permutation — Bypassed

Category Swapping Between Similar Rows

Occasionally swapping categories between similar rows was considered to create slight variations. This was bypassed because, without complex cluster-bounding, it risks generating illogical feature combinations (e.g., a "Fitness + Giveaway" profile with "Tech + Product Launch" metrics) that introduce artificial bias into downstream regression.

Chosen Approach: Bootstrapping + Vectorized Gaussian Noise is computationally O(n) linear time, runs in seconds even at 1M scale, and preserves both categorical proportions and continuous statistical structure.

Phase 1.3 — Pre-Augmentation

Feature Selection & Dimensionality Reduction

Before augmentation, specific columns are dropped and missing values are eliminated to ensure the noise injection targets only clean, predictive signals.

Temporal Data Handling

Date columns (start_date, end_date) are explicitly dropped prior to augmentation. Specific timestamps lack linear correlation with engagement KPIs and risk introducing target leakage or requiring arbitrary date imputation.

Missing Value Treatment

Any row containing NaN values is dropped prior to augmentation to prevent the algorithm from mathematically multiplying errors across the 850K generated rows.

Phase 1.3 — Implementation

Augmentation Pipeline: Full Code Flow

The complete pipeline in augmenter_pipeline.py — from ingestion through noise injection to final export:

def augment_data_with_noise(input_path, output_path, target_rows=1000000, noise_std=0.01):
    df = pd.read_csv(input_path)
    
    # 1. Drop dates & NaN rows
    df.drop(columns=['start_date', 'end_date'], inplace=True, errors='ignore')
    df.dropna(inplace=True)
    
    rows_to_generate = target_rows - len(df)
    
    # 2. Separate numerical and categorical columns
    num_cols = df.select_dtypes(include=[np.number]).columns.tolist()
    
    # 3. Bootstrap: sample with replacement
    synthetic_base = df.sample(n=rows_to_generate, replace=True, random_state=42).reset_index(drop=True)
    
    # 4. Gaussian Noise Injection (vectorized)
    col_stds = df[num_cols].std().values
    noise_matrix = np.random.normal(0.0, 1.0, (rows_to_generate, len(num_cols))) * col_stds * noise_std
    synthetic_base[num_cols] = synthetic_base[num_cols] + noise_matrix
    
    # 5. Concatenate & shuffle
    final_df = pd.concat([df, synthetic_base], ignore_index=True)
    final_df = final_df.sample(frac=1, random_state=42).reset_index(drop=True)
    
    # 6. Export 1M rows
    final_df.to_csv(output_path, index=False)

The Algebra

Each of these features contains product_sales in its numerator. The Random Forest simply reverse-engineered the division:

sales_velocity × duration ≈ product_sales

The algorithm did not discover a predictive business pattern — it reconstructed the algebra.

Business Intelligence

Key Findings from the Audit

Finding 1: Vanity Metrics Do Not Drive Revenue

Across four independent regression models, raw engagement counts, reach, and platform selection showed zero linear predictive power for product sales (R² ≈ 0 in all cases). High engagement does not equal high conversion. Brands chasing follower counts and like totals are optimizing for a metric that is mathematically disconnected from revenue.

Finding 2: Virality Does Not Scale Linearly with Sales

The Model 3 A/B test confirmed that campaigns flagged as viral outliers (extreme engagement-to-reach ratios) showed no improvement in sales prediction compared to normal campaigns. Algorithmic virality generates attention, not revenue. Conversion remains dependent on audience quality and trust, not algorithmic amplification.

Finding 3: Social Media Marketing Is Highly Non-Linear

The fundamental relationship between social media metrics and sales is non-linear. Linear regression is structurally incapable of capturing the conversion dynamics at play. This suggests that conversion is driven by latent factors — audience trust, niche specificity, and content-market fit — that are not captured in standard platform analytics.

Finding 4: Target Leakage Is a Real Enterprise Risk

Model 5 demonstrated how easily a near-perfect R² can be achieved through target leakage. In a production environment, deploying such a model would create false confidence in predictions that are mathematically circular rather than genuinely predictive.

Strategic Recommendations

Actionable Marketing Strategy

1. Deprioritize Vanity Metrics in ROI Reporting

Stop using raw reach, impressions, and engagement counts as KPIs for marketing ROI. Instead, track normalized conversion rates (reach-to-sales, engagement-to-sales) and benchmark them against platform-specific averages.

2. Invest in Niche-Specific, High-Trust Influencers

Since conversion depends on audience quality rather than reach volume, brands should invest in micro and mid-tier influencers with demonstrated conversion histories in specific niches, rather than chasing viral macro-influencers.

3. Implement Short-Duration Campaign Strategies

Descriptive analytics (Tableau) showed that peak engagement momentum is exhausted within 2–4 days. Campaign budgets should be concentrated in short, intensive bursts rather than spread thinly over weeks.

4. Enforce Strict Feature Auditing in ML Pipelines

Before deploying any predictive model, implement a mandatory feature audit to check for algebraic relationships between features and the target variable. Target leakage can produce deceptively perfect metrics while providing zero real-world predictive value.

5. Explore Non-Linear Modeling

Given that linear regression failed across all configurations, future work should explore gradient-boosted models (XGBoost, LightGBM) with proper feature engineering, or deep learning approaches that can capture the non-linear conversion dynamics.

6. Use Platform-Relative Benchmarks

The benchmark index features engineered in our pipeline allow fair cross-platform comparison. A campaign should be evaluated against its own platform's baseline, not against absolute numbers that vary wildly between TikTok, YouTube, Instagram, and Twitter.
